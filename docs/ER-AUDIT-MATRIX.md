# Entity-to-implementation audit

Source design: `DATABASE.md` Mermaid diagram and the recorded supplied-diagram interpretation in `ER-REVIEW-AND-CHANGES.md`. The original externally supplied image is not stored as an independently inspectable repository asset. No design was changed to force a test result.

Every public table has a UUID `id` primary key. Exact columns, data types, nullability, defaults, all foreign-key delete rules, checks, indexes and policies are exported from the hosted database in [audit-evidence.json](audit-evidence.json). The following covers every entity; “tested” refers to the named workflows, not every possible field combination.

## Design differences retained

- Passwords live in Auth, not a second public credential table.
- A public shop address is not linked to a customer's private saved address.
- The documented earlier **zero-payment MVP** takes precedence over the old diagram's payment branch. Payments remain intentionally absent, not silently declared implemented.
- `PLACED` is the order's pending state. Shop operating state and moderation state are separate checked-text enums.
- The design supports customer–shopkeeper chat, not customer–customer chat.
- Additional tracking, audit and singleton settings tables implement recorded project requirements. Cart persistence is browser-side; there is no server cart or cross-device cart synchronization.
- Image URL columns are text references, not foreign keys to Storage. Private message paths are validated against an existing object by the RPC. Orphan-file lifecycle cleanup is not implemented.
